# packages/pg-prime-testing/src/index.ts

## Purpose
The single entry point of `@pg-prime/testing`, the test-helper package for `pg-prime`. It only re-exports the five modules: the tier-0 mock pool and `expectSql`, the tier-1 PGlite fixture and bridge, the tier-2 container and scratch-database fixtures, and the skip guards. Consumers import it as `@pg-prime/testing` (e.g. the scaffolded `packages/pg-prime-create/templates/test/setup.ts:3`).

## Flow
1. Pure re-exports; importing the entry runs no I/O. The optional peers `@electric-sql/pglite` and `@testcontainers/postgresql` are loaded lazily inside `startPglite` / `startPostgres` / `dockerAvailable`, not at import time.
2. `package.json` maps `.` to `dist/index.js`, with a `types@<5.9` condition first that resolves to `dist/unsupported-typescript.d.ts` (`packages/pg-prime-testing/package.json`).

## Gotchas
- `spuriousReadyForQuery` is exported from `pglite-bridge.ts` (`packages/pg-prime-testing/src/pglite-bridge.ts:260`) but not from this entry; only the `pg-prime` repo's own `packages/pg-prime/test/live/bridge.unit.test.ts` reaches it, via the re-export shim `packages/pg-prime/test/live/_pglite-bridge.ts`.
- `pg-prime` is a required peer; `postgres.ts` imports it eagerly (`packages/pg-prime-testing/src/postgres.ts:21`), so importing the entry needs `pg-prime` installed even for a mock-only suite.
- Nothing in the package imports a test runner; guards take the runner's `it` (`packages/pg-prime-testing/src/guards.ts:35`).
- `src/unsupported-typescript.d.ts` is generated by `tools/api-snapshot.mjs` and is what TypeScript < 5.9 consumers resolve: every export is an `{ ERROR: '…requires TypeScript >= 5.9…' }` stand-in. Do not edit it by hand.
- The public surface is goldened in `tools/api-snapshot/pg-prime-testing.json` (driven by `tools/api-snapshot.mjs:55`); adding or removing an export here changes that snapshot.
- The package has no runtime `dependencies`; all three of `pg-prime`, `@electric-sql/pglite`, `@testcontainers/postgresql` are peers.

## Tests
- No spec targets the entry itself; each module has its own (see the sibling docs). The test files import from `../../src/<module>.js`, not from `index.ts`.
- The published shape (export map, d.ts) is exercised by `tools/pack-smoke.mjs` and `tools/check-dts.mjs` (`zeroDeps: false` at `tools/check-dts.mjs:46`).
- Vitest projects (`packages/pg-prime-testing/vitest.config.ts`): `unit` = `test/unit`, `live` = `test/live` (PGlite), `pg` = `test/pg` (needs `PG_PRIME_TEST_URL` and/or Docker). Run e.g. `pnpm --filter @pg-prime/testing exec vitest run --project unit`.
- In tests, `pg-prime` resolves to its source via per-project aliases in `vitest.config.ts`, not to `dist/`.
