# packages/pg-prime-create/src/scaffold.ts

## Purpose
Writes a new pg-prime project from `templates/`: refuses a non-empty target, renders `{{token}}` placeholders and `testing` blocks, merges the testing `package.json` fragment, and creates an empty `migrations/`. Called by `main` (`packages/pg-prime-create/src/main.ts:68`) and re-exported as a library function by `packages/pg-prime-create/src/index.ts:10`; `packageNameFor` is used by `resolveOptions` (`packages/pg-prime-create/src/prompts.ts:96`). Reads `VERSIONS` from the generated `src/versions.ts`.

## Public API
- `templatesDir(): string` — `dist/templates/` when it exists beside the module, else the package's `templates/`.
- `packageNameFor(dir): string` — last path segment, lowercased, invalid characters → `-`, leading/trailing `-_.` trimmed; empty → `'app'`.
- `scaffold(options: ScaffoldOptions): ScaffoldResult` — writes the project; throws if `dir` exists and is not empty, or a template uses an unknown token.

## Flow
1. If `dir` exists, entries other than `.git` and `.DS_Store` cause an `Error` listing up to five of them (`packages/pg-prime-create/src/scaffold.ts:165-173`, `:160`).
2. Tokens are `name`, `pm`, `pmRun`, `pmExec` (from `PM_COMMANDS`) plus every `VERSIONS` key (`tokensFor`, `:71-80`).
3. For each `BASE` file (8) and, with `testing`, each `TESTING` file (3) (`:43-58`), the template is read, `applyTestingBlocks` keeps or drops lines between `<!-- testing:start -->`/`<!-- testing:end -->` (markers always removed, `:95-112`), then `render` replaces `{{word}}` tokens (`:82-88`).
4. `write` creates parent directories and writes to `dir`, recording the `/`-separated relative path (`:182-187`).
5. `templates/package.json` is rendered and parsed; with `testing`, `templates/package.testing.json` is merged in: `scripts` keep insertion order, dependency maps are sorted by key (`mergePackageJson`, `:115-133`, `:194-205`).
6. `package.json` is written as 2-space JSON with a trailing newline, then an empty `migrations/.gitkeep` (`:206-210`).
7. Returns `{ dir, files }` with `files` sorted (`:212`).

## Gotchas
- `src/versions.ts` is generated by `scripts/versions.mjs` and git-ignored; without it this module does not import. Run `node scripts/versions.mjs` (or `build`/`typecheck`/the test `globalSetup`) first.
- Templates for dotfiles are stored undotted (`gitignore`, `env.example`) because npm strips `.gitignore` from tarballs (`:36-46`).
- Four templates are byte-equal to code blocks of `docs/src/content/docs/guides/getting-started.mdx` (`schema.ts`, `pg-prime.config.ts`, `db.ts`, `index.ts` ↔ `first-query.ts`); `test/templates.test.ts` fails on drift and the page wins.
- Every BASE/TESTING template is rendered, so any literal `{{word}}` in a template throws `templates/<file>: no value for {{word}}` (`:85`).
- The refusal runs before any write, but a failure mid-way (e.g. an unknown token) leaves a partially written directory.
- `tools/build-package.mjs` copies `templates/` into `dist/`; `templatesDir` falls back to the source tree in this repo (`:17-27`).
- `PM_COMMANDS` (`:61-68`) is duplicated by `nextSteps` in `packages/pg-prime-create/src/main.ts:37-38`.
