# 17 — `@pg-prime/mq`: work queues and workers on PostgreSQL. Design & Implementation Plan

2026-10-08. Branch `feat/mq`. **Status: PLAN — for revmux review before any code.**
Family rules (dependency graph, shared helpers, ledgers, packaging, budgets, cross-plan order) are
in [15-events §0](./15-events.md). Pub/sub, channels and the event log belong to
[15-events](./15-events.md). The outbox is [16-outbox](./16-outbox.md) and scheduling is
[18-cron](./18-cron.md).

`@pg-prime/mq` provides point-to-point work queues with competing consumers: a claim with
`SKIP LOCKED`, a lease and a token, retries with backoff, delay, priority, dedup, global and
per-group rate and concurrency limits, flows (parent/children), a dead-letter (`failed`) state, retention, and
transactional send and complete. It depends on `@pg-prime/events` for wake-ups, message-state
notifications and topic→queue bindings. It does not
duplicate any of that machinery.

**Goals.**
1. Every transition is one SQL statement or one short transaction.
2. Each guarantee has a named tier-2 test: no message has two valid owners, an expired lease is
   recovered once, and a parent is released once.
3. `send` and completion accept `{ tx }`, so handlers whose effects live in the same database get
   exactly-once effects.
4. PostgreSQL 15–18, PgBouncer transaction mode (by polling), Node and Bun.

**Prior art.** BullMQ 6.3.11's own PostgreSQL backend was considered and not used: it owns its
connections (no caller transaction) and takes claim time from the client clock.

## 1. Decisions

| # | Decision | One-line reason |
|---|---|---|
| D1 | Schema `pgprime_mq`, its own ledger, migrations through core's `migrateOwnedSchema` (15 §0.3); `migrationSql()` for kit vendoring | family rule |
| D2 | **Depends on `@pg-prime/events`** (a real dependency, not a peer), for three things: `waker()` for every wake-up; `engineChannel()`/`engineChannelSql()` for wake and watch channels; subscriptions for `bind()`. The events *schema* is created only when a binding is used | No second LISTEN/poll loop, channel-hash scheme or log. events' bytes are inside mq's tree-shake budget (15 §0.4) |
| D3 | **One `messages` table**, state as an enum, a partial index per hot path, no partitioning | A cross-partition `UPDATE` raises `40001` under concurrency, which breaks `SKIP LOCKED` claims |
| D4 | Every transition is a CTE statement built in TS; short transactions only for flow-failure cascades and multi-step admin. No PL/pgSQL | Atomic without stored code; a rolling deploy never swaps a function body |
| D5 | **Gate only on counters of locked rows** (group `active`, queue `active`, rate windows on the `groups`/`queues` row) | READ COMMITTED + EvalPlanQual (§5.4) |
| D6 | **Lease + token.** A claim sets `token`/`lease_until`; every consumer write is `WHERE id AND token AND state = 'active'`; 0 rows → `LeaseLostError`. **An expired lease counts as a failed attempt**, with backoff | One concept instead of separate "stalled" and "attempts" counters; a poison message that kills its worker still reaches `failed` |
| D7 | DB clock only (15 §0.5) | clock skew changes nothing |
| D8 | Payload `jsonb`, typed by `defineQueue<T, R>()` or inferred from a Standard Schema validator; optional `codec`; limits 1 MiB payload/result, 64 KiB progress; `\u0000` refused with path | typed, zero deps |
| D9 | `ifVersion`/`executeRowCount` are not used | builder-only; the token guard + `RETURNING` is the same check in one round trip |
| D10 | **Retention and retry policy are declared on the queue** and synced to the `queues` row; per-message overrides cover retry only | Count-based retention is a queue-wide notion; this avoids "last writer wins" |
| D11 | **Dependencies are created with their waiter**: flows are inserted atomically, and dynamic children are spawned by their active parent. Never attached to an existing message | A completer cannot see a dependency row committed after its statement snapshot |
| D12 | Dependencies: `@pg-prime/events` only; peer `pg-prime`; `fixed` group (0.2.0); Bun gated; ≤ 350 KB unpacked, install ≤ 600 KB including events (15 §0.4) | family rule |

## 3. Statement conventions

- **Statements** are `db.sql` / `tx.sql` with `sql.ident(schema, …)`, labelled `mq.<op>` through
  `withOptions({ label })`, so they show up in `db.observe`, the slow log and OTel spans.
- **Short transactions** use `db.transaction`; locks are `Tx.advisoryLock` (xact family) only.
- **Errors** extend `PgPrimeError` (`MQ_*`). An `IndeterminateCommitError` on completion is
  resolved by re-reading the row (§8).
- **One `finish` builder.** Every transition into a terminal state (`completed`, `failed`,
  `cancelled`) is built by one function, `finish(id, to, guard)`, whatever the path: completion,
  final failure, expired final attempt, cascade, cancel. It always carries the full fragment set
  that the message's own columns call for: `[group]`/`[global]` (only if it was active and
  counted), `[dedup]`, `[deps]`, `[watch]`, `expire_at`, and the delete-variant. So no path can
  leak a dedup key or a counter. `guard` is one of:
  - `token` (the owner);
  - `flagged` (the owner of a message `cancel()` flagged, when a move out of `active` refuses it);
  - `expired` (lease-expiry scan);
  - `blocked` (cascade on a parent);
  - `idle` (cancel of a ready, delayed or blocked message of the cancelling queue).

  The fragments are pure functions with golden-SQL tests.
- **Traps** (15 §0.5): an unreferenced `SELECT` CTE does not run; never modify a row twice in one
  statement.

## 4. Data model — migration v1

`pgprime_mq` is substituted via `sql.ident(schema)`; the ledger table is created by
`migrateOwnedSchema`.

```sql
create type pgprime_mq.msg_state  as enum ('ready', 'delayed', 'active', 'completed', 'failed', 'cancelled', 'blocked');
create type pgprime_mq.dep_status as enum ('pending', 'completed', 'failed', 'ignored');
create type pgprime_mq.on_fail    as enum ('wait', 'fail', 'ignore');

create sequence pgprime_mq.msg_seq;          -- ids and FIFO order; LIFO stores -nextval

create table pgprime_mq.queues (
  name           text primary key,
  paused         boolean not null default false,
  limited_until  timestamptz,
  rate_max       int,
  rate_ms        int,
  rate_window    timestamptz,
  rate_count     int not null default 0,
  concurrency    int,
  active         int not null default 0,      -- counts `counted` messages only (D5)
  keep_completed_ms bigint, keep_completed_n int,
  keep_failed_ms    bigint, keep_failed_n    int,
  watch          boolean not null default false,  -- as built: [watch] reads it, so every process emits
  maint_at       timestamptz not null default '-infinity',
  expire_at      timestamptz not null default '-infinity',   -- lease-expiry scan gate
  created_at     timestamptz not null default now()
) with (fillfactor = 50);

create table pgprime_mq.messages (
  id            bigint primary key,
  queue         text not null,
  state         pgprime_mq.msg_state not null,
  payload       jsonb not null,
  key           text,                        -- caller's idempotency / dedup key
  priority      int not null default 0,      -- lower runs first
  order_key     bigint not null,
  run_at        timestamptz,
  group_key     text,
  attempts      int not null default 0,      -- settled attempts
  claims        int not null default 0,
  retry         jsonb not null,              -- resolved policy { maxAttempts, baseDelayMs, maxDelayMs, jitter }
  token         text,
  lease_until   timestamptz,                 -- in no index: heartbeats stay HOT
  consumer      text,
  progress      jsonb,
  result        jsonb,
  error         text,
  stack         text,
  parent        bigint,
  on_fail       pgprime_mq.on_fail not null default 'wait',
  pending_deps  int not null default 0,
  dedup_key     text,
  cancel        boolean not null default false,
  counted       boolean not null default false,  -- claimed under the queue's global limits; `[global]` decrements only these
  child_failed  boolean not null default false,  -- a child with on_fail = 'fail' failed while this parent was active (§5.6)
  expire_at     timestamptz,                 -- age retention, set at finish
  created_at    timestamptz not null default clock_timestamp(),
  started_at    timestamptz,
  finished_at   timestamptz
) with (fillfactor = 70,
        autovacuum_vacuum_scale_factor = 0.02,
        autovacuum_vacuum_insert_scale_factor = 0.02,
        autovacuum_analyze_scale_factor = 0.02);

create index messages_ready    on pgprime_mq.messages (queue, priority, order_key) where state = 'ready' and group_key is null;
create index messages_ready_g  on pgprime_mq.messages (queue, group_key, priority, order_key) where state = 'ready' and group_key is not null;
create index messages_delayed  on pgprime_mq.messages (queue, run_at) where state = 'delayed';
create index messages_active   on pgprime_mq.messages (queue) where state = 'active';
create index messages_finished on pgprime_mq.messages (queue, state, finished_at) where state in ('completed', 'failed', 'cancelled');
create index messages_key      on pgprime_mq.messages (queue, key) where key is not null;
create index messages_parent   on pgprime_mq.messages (parent) where parent is not null;
create index messages_expire   on pgprime_mq.messages (expire_at) where expire_at is not null;

create table pgprime_mq.groups (                  -- counters only; which groups have ready work comes from messages_ready_g (S5)
  queue text not null, key text not null,
  paused boolean not null default false,
  concurrency int, active int not null default 0,
  rate_max int, rate_ms int, rate_window timestamptz, rate_count int not null default 0,
  limited_until timestamptz,
  primary key (queue, key)
) with (fillfactor = 50);

-- No FK on child: a retention-deleted child's result must survive for its parent.
create table pgprime_mq.deps (
  parent bigint not null references pgprime_mq.messages (id) on delete cascade,
  child  bigint not null,
  child_queue text not null,
  status pgprime_mq.dep_status not null default 'pending',
  value  jsonb,
  primary key (parent, child)
);
create index deps_child   on pgprime_mq.deps (child);
create index deps_pending on pgprime_mq.deps (child) where status = 'pending';

create table pgprime_mq.dedup (
  queue text not null, key text not null,
  msg bigint not null,
  expire_at timestamptz,                         -- null: held until the message finishes
  primary key (queue, key)
);
create index dedup_msg on pgprime_mq.dedup (msg);
```

### 4.1 Index → ordering map, bloat

| Path | Index | Contract |
|---|---|---|
| claim | `messages_ready (queue, priority, order_key)` | lower `priority` first; FIFO by `order_key`; LIFO stores `-nextval`; a re-queue takes a fresh `nextval` and keeps its sign |
| claim in groups | `messages_ready_g (queue, group_key, …)` | a skip scan over it enumerates exactly the groups that have ready messages (round-robin from a per-worker cursor); FIFO within a group |
| promote | `messages_delayed (queue, run_at)` | earliest due first |
| lease expiry, counts | `messages_active (queue)` | bounded by total consumer concurrency; `lease_until` is filtered on the heap |

- `fillfactor 70` on `messages`, 50 on the counter tables. Heartbeat, progress and counter bumps
  touch only unindexed columns, so they are HOT updates.
- Retention deletes in batches of ≤ 1 000 rows (`FOR UPDATE SKIP LOCKED`), so no statement comes
  near pg-prime's 30 s `statement_timeout`.

## 5. Queues

### 5.1 States and transitions

`ready · delayed · active · completed · failed · cancelled · blocked` (`blocked` = waiting for
children). `failed` is the dead-letter state: list, inspect, `retry` or `purge` it.

| # | From → To | Trigger | Stmt |
|---|---|---|---|
| T1 | ∅ → ready / delayed | `send`, `sendMany`, topic binding (§6.2) | S1 |
| T2 | ∅ → blocked (+ children ∅ → ready/delayed) | `flow` | F1 |
| T3 | delayed → ready | due, `promote` | S2 |
| T4 | ready → active | claim | S3 / S4 / S5 |
| T5 | active → completed (or deleted) | handler resolved, `ctx.complete(…, { tx })` | S7 |
| T6 | active → ready / delayed | failure with attempts left | S8r |
| T7 | active → failed | final failure, `NonRetryableError` | S8f = `finish` (+ cascade tx) |
| T8 | active → delayed | `ctx.defer({ delayMs \| until })` | S12 (no attempt) |
| T9 | active → ready | `ctx.rateLimit(ms)`, shutdown release | S13 (no attempt) |
| T10 | active → blocked | `ctx.waitForChildren()` with pending deps | S14 |
| T11 | active → ready / delayed / failed | lease expired (D6) | S9 |
| T12 | blocked → ready | last dep resolved (completed or ignored) | `finish` `[deps]` |
| T13 | blocked → failed | child failed with `fail` policy (propagates) | cascade |
| T14 | ready / delayed / blocked → cancelled; active → abort signal, then failed/cancelled | `cancel` | A-cancel |
| T15 | failed / cancelled / completed → ready | `retry` (also restores a `wait` dependency to `pending`) | A-retry |
| T16 | any but active → ∅ | `remove`, `purge`, retention, `drop` | A-*, S10 |

### 5.2 Hot statements

Params are named for reading; the code uses `sql` holes.

**S1 send / sendMany** — 1 or N messages as one `jsonb` array (no 65 535-parameter ceiling).
Duplicate dedup keys inside one batch are collapsed client-side (`ON CONFLICT DO UPDATE` cannot
touch a row twice).

```sql
with src as (
  select nextval('pgprime_mq.msg_seq') as id, r.*
  from jsonb_to_recordset($msgs) as r(payload jsonb, key text, priority int, lifo bool,
       delay_ms bigint, group_key text, retry jsonb, dedup text, dedup_ms bigint,
       dedup_extend bool)
), d as (                                             -- decided only from the locked dedup row (15 §0.5 rule 3)
  insert into pgprime_mq.dedup as x (queue, key, msg, expire_at)
  select $q, dedup, id, now() + dedup_ms * interval '1 ms' from src where dedup is not null
  on conflict (queue, key) do update
    set msg       = case when x.expire_at <= now() then excluded.msg else x.msg end,      -- reclaim an expired window
        expire_at = excluded.expire_at                                                     -- reclaim or extend
    where x.expire_at <= now() or (excluded.expire_at is not null and $extend)
  returning key, msg
), ins as (
  insert into pgprime_mq.messages (id, queue, state, payload, key, priority, order_key, run_at,
                                   group_key, retry, dedup_key)
  select id, $q, (case when delay_ms > 0 then 'delayed' else 'ready' end)::pgprime_mq.msg_state,
         payload, key, priority, case when lifo then -id else id end,
         case when delay_ms > 0 then now() + delay_ms * interval '1 ms' end,
         group_key, retry, dedup
  from src
  where dedup is null or exists (select from d where d.key = src.dedup and d.msg = src.id)
  returning id, state, group_key
), g as (                                             -- new groups only; an existing row is never locked
  insert into pgprime_mq.groups (queue, key)
  select distinct $q, group_key from ins where group_key is not null
  on conflict do nothing
), w as (select pg_notify($chan, case when bool_or(state = 'delayed') then 'd' else 'w' end) from ins having count(*) > 0)
select ins.id, ins.state, (select count(*) from w) as woke from ins
```

- **Deduplication.** A message whose dedup key did not come back from `d` with its own id was
  deduplicated. The client reads the surviving ids in a follow-up `select key, msg from dedup` in
  the same transaction (a fresh snapshot, so it sees the winner), and returns
  `{ id: <existing>, deduplicated: true }`.
- **Reclaim is decided only from the locked dedup row** (`expire_at <= now()`); the sender never
  looks at `messages`, whose state it would read from a stale snapshot.
- One S1 statement carries one dedup mode (`$extend` is a statement parameter).
  `sendMany` groups items by mode, so a mixed batch is a few statements in the same transaction.
- **Dedup modes:**
  - `until-done` (default): `expire_at` null. The row is deleted by the finishing statement
    (`[dedup]`), and by `cancel`/`remove`/`purge`/`drop` in the statements that delete or cancel
    the message.
  - `windowMs` (throttle).
  - `windowMs` + `extend` (debounce): a duplicate extends `expire_at`.
- **S1's core (`src` → `ins` → `g` → `w`) is the only way a message is inserted.** F1 (flows) and
  `ctx.spawn` reuse it with extra columns (`parent`, `on_fail`, `state = 'blocked'`), so every
  grouped message, in a flow or not, has its group row.
- Groups: S1 inserts a row only for a **new** group (`DO NOTHING` never locks an existing row), so
  a long caller transaction never holds a group row that claims or settles need. S5 finds ready
  groups from `messages_ready_g` itself, so there is no hint to maintain.
- Queue and group configuration is upserted by `start()` (15 §0.3), outside any caller
  transaction, so S1 never touches `queues`.

**S2 promote** — timer-driven per consumer; `SKIP LOCKED` keeps concurrent runs disjoint.

```sql
with due as (
  select id from pgprime_mq.messages
  where queue = $q and state = 'delayed' and run_at <= now()
  order by run_at limit 1000 for update skip locked
), up as (
  update pgprime_mq.messages m set state = 'ready', run_at = null,
         order_key = sign(m.order_key) * nextval('pgprime_mq.msg_seq')
  from due where m.id = due.id returning m.id
)
select (select count(*) from up) as promoted, now() as db_now,
       (select min(run_at) from pgprime_mq.messages where queue = $q and state = 'delayed' and run_at > now()) as next_at
```

**S3 claim — fast path** (no global limits, no groups):

```sql
with next as (
  select id from pgprime_mq.messages
  where queue = $q and state = 'ready' and group_key is null
    and exists (select from pgprime_mq.queues where name = $q and not paused
                and coalesce(limited_until, '-infinity') <= now())
  order by priority, order_key
  limit $n
  for update skip locked
)
update pgprime_mq.messages m
set state = 'active', token = coalesce($tok, gen_random_uuid()::text),
    lease_until = now() + $lease * interval '1 ms', consumer = $c,
    started_at = clock_timestamp(), claims = m.claims + 1
from next where m.id = next.id
returning m.*, now() as db_now
```

`$n` is the number of free slots, so one claim serves them all. `RETURNING` order is unspecified;
the client sorts by `(priority, order_key)`.

**S4 claim — global rate limit and/or global concurrency.** The queue row is locked (waiting, not
skipping), and the counters are on it (D5).

```sql
with q as (
  select name, rate_max, rate_ms, concurrency, active,
         (rate_window is null or rate_window + rate_ms * interval '1 ms' <= now()) as fresh,
         case when rate_window is null or rate_window + rate_ms * interval '1 ms' <= now() then 0 else rate_count end as used
  from pgprime_mq.queues
  where name = $q and not paused and coalesce(limited_until, '-infinity') <= now()
  for update
), next as (
  select id from pgprime_mq.messages
  where queue = $q and state = 'ready' and group_key is null
  order by priority, order_key
  limit coalesce((select greatest(0, least($n, coalesce(rate_max - used, $n), coalesce(concurrency - active, $n))) from q), 0)
  for update skip locked
), up as (update pgprime_mq.messages m set /* as S3 */ …, counted = (select concurrency is not null from q)
          from next where m.id = next.id returning m.*
), qu as (
  update pgprime_mq.queues u set
    rate_window   = case when q.fresh then now() else u.rate_window end,
    rate_count    = q.used + (select count(*) from up),
    active        = u.active + case when u.concurrency is null then 0 else (select count(*) from up) end,
    limited_until = case when q.rate_max <= q.used + (select count(*) from up)
                         then coalesce(case when q.fresh then now() end, u.rate_window) + q.rate_ms * interval '1 ms'
                         else u.limited_until end
  from q where u.name = q.name
)
select up.*, now() as db_now from up
```

The outer `coalesce(…, 0)` matters: a paused queue yields no `q` row, and `LIMIT NULL` means
*unlimited*. A spent window sets `limited_until`, so every other consumer's S3/S4 skips the queue
without touching its lock.

**S5 claim — groups.**
- A **skip scan** over `messages_ready_g` lists exactly the groups that have ready messages,
  starting after the worker's round-robin cursor `$after`. There is no hint table to keep in sync.
- The group rows are then claimed with `SKIP LOCKED`.
- Caps come from the row or the worker's defaults. An unset concurrency is bound as `2147483647`,
  never `NULL`, because `active < NULL` would exclude every group.

```sql
with recursive keys(k) as (
  (select group_key from pgprime_mq.messages
   where queue = $q and state = 'ready' and group_key > $after
   order by group_key limit 1)
  union all
  select (select m.group_key from pgprime_mq.messages m
          where m.queue = $q and m.state = 'ready' and m.group_key > keys.k
          order by m.group_key limit 1)
  from keys where keys.k is not null
), cand as (
  select k from keys where k is not null limit $scan                -- default 4 × $n
), g as (
  select key,
         least(coalesce(concurrency, $gc) - active,
               case when coalesce(rate_max, $gmax) is null then $n
                    when rate_window is null or rate_window + coalesce(rate_ms, $gms) * interval '1 ms' <= now()
                      then coalesce(rate_max, $gmax)
                    else coalesce(rate_max, $gmax) - rate_count end) as free
  from pgprime_mq.groups
  where queue = $q and key in (select k from cand) and not paused and active < coalesce(concurrency, $gc)
    and coalesce(limited_until, '-infinity') <= now()
    and exists (select from pgprime_mq.queues where name = $q and not paused and coalesce(limited_until, '-infinity') <= now())
  order by key
  for update skip locked
), pick as (
  select c.id, g.key from g
  cross join lateral (
    select id from pgprime_mq.messages m
    where m.queue = $q and m.group_key = g.key and m.state = 'ready'
    order by priority, order_key limit greatest(g.free, 0)
    for update skip locked
  ) c
  limit $n
), up as (update pgprime_mq.messages m set /* as S3 */ … from pick where m.id = pick.id returning m.*
), gu as (
  update pgprime_mq.groups r set active = r.active + t.n /* , rate window as S4 */
  from (select group_key, count(*) as n from up group by 1) t
  where r.queue = $q and r.key = t.group_key
)
select meta.cursor, meta.scanned, meta.db_now, up.*
from (select coalesce((select max(group_key) from up), (select max(k) from cand)) as cursor,   -- last group served, else past the ineligible
             (select count(*) from cand) as scanned, now() as db_now) meta
left join up on true                                   -- one metadata row even when nothing was claimed
```

- **Round robin.** The worker's next `$after` is `cursor`:
  - the largest group actually served, so eligible groups that `limit $n` did not reach are first
    next time;
  - or, when nothing was claimed, the end of the scan, so paused or full groups are passed over. When
  nothing was claimed and `scanned < $scan` (the scan reached the end), it resets to `''`.
  - As built: the reset applies only when nothing was claimed (resetting after a claim skipped the
    groups past the last one served), and a round that claimed nothing from a non-empty cursor
    retries once from `''`.
  - As built: `keys` needs its column list, `keys(k)`; M-Q4 (the outer reference in the LATERAL
    `LIMIT` and the skip scan beside data-modifying CTEs) holds on PG 15.19, 16.15, 17.11 and 18.6.
- **Global limits** (`queues.concurrency` or `rate`) apply to grouped messages too. The S5 variant
  for such a queue adds S4's `q` CTE (the queue row `for update`, taken **before** the group rows,
  the same order every claim uses). It caps `pick`'s outer `limit` by the global free capacity, sets
  `counted = true` and adds S4's `qu` update.
- **No deadlock.** Settles lock message → group → queue, but a claim never *waits* on a message or
  group row (`SKIP LOCKED`), so there is no cycle.
- A queue with both grouped and ungrouped ready messages alternates S3/S4 and S5, fetch by fetch.

**S6 heartbeat** — one statement for every message the worker holds, every `heartbeatMs`
(default `leaseMs / 3`):

```sql
with h as (
  select m.id from pgprime_mq.messages m
  join unnest($ids::bigint[], $toks::text[]) as t(id, token) on m.id = t.id and m.token = t.token
  where m.state = 'active'
  for update of m skip locked                      -- a row held by an open caller tx must not block the others
)
update pgprime_mq.messages m set lease_until = now() + $lease * interval '1 ms'
from h where m.id = h.id
returning m.id, m.cancel
```

- `ctx.complete(…, { tx })` removes its message from the heartbeat set first.
- An id missing from the result is checked with an unlocked `select token, state` (it may only be
  locked by a short admin update). Token gone or state changed → the lease is lost, and the
  message's `AbortSignal` aborts with `LeaseLostError`.
- `cancel = true` aborts it with `CancelledError`.

**S7 complete** = `finish(id, 'completed', token)`, shown with all its fragments:

```sql
with done as (
  update pgprime_mq.messages set state = 'completed', result = $res::jsonb, finished_at = clock_timestamp(),
         attempts = attempts + 1, token = null, lease_until = null,
         expire_at = clock_timestamp() + $keep_ms * interval '1 ms'
  where id = $id and token = $tok and state = 'active'
  returning id, queue, group_key, parent, dedup_key, counted
)
-- [group]  , gd as (update pgprime_mq.groups g set active = g.active - 1 from done where g.queue = done.queue and g.key = done.group_key)
-- [global] , qd as (update pgprime_mq.queues u set active = u.active - 1 from done where u.name = done.queue and done.counted)
-- [dedup]  , dd as (delete from pgprime_mq.dedup x using done where x.queue = done.queue and x.key = done.dedup_key and x.msg = done.id and x.expire_at is null)
-- [deps]   , dp as (update pgprime_mq.deps d set status = 'completed', value = $res::jsonb
--                   from done where d.parent = done.parent and d.child = done.id and d.status = 'pending' returning d.parent),
--            pr as (update pgprime_mq.messages p set
--                     pending_deps = p.pending_deps - 1,
--                     state = case when p.pending_deps = 1 and p.state = 'blocked' then 'ready' else p.state end,
--                     order_key = case when p.pending_deps = 1 and p.state = 'blocked' then sign(p.order_key) * nextval('pgprime_mq.msg_seq') else p.order_key end
--                   from dp where p.id = dp.parent returning p.queue, p.state),
--            pw as (select pg_notify(<chan(pr.queue)>, 'w') from pr where pr.state = 'ready')
-- [watch]  , ev as (select pg_notify($watch_chan, json_build_object('id', id, 's', 'completed')::text) from done)
select done.*, (select count(*) from ev) as e from done   -- each fragment's count is referenced
```

- A queue that keeps no completed messages swaps `done` for
  `delete … where id = $id and token = $tok and state = 'active' returning …`. The `[deps]`
  fragment still records the result, so the parent's `ctx.childResults()` survives the child's
  deletion.
- Siblings completing together serialize on the parent row. At READ COMMITTED the second `UPDATE`
  re-reads the decremented version (EvalPlanQual), so exactly one sees `pending_deps = 1`, and the
  parent is released once.
- `[watch]` is in every transition statement of a queue declared with `watch: true`, whichever
  process settles it. Its payload is ids and state only, on the events engine channel
  `engineChannel(schema, 'q-watch', queue)` (§6.1).
- `[deps]` for a **failed** child (`finish(…, 'failed', …)`) follows its `on_fail`:
  - `wait` → status `failed`, and the parent's count is kept;
  - `ignore` → status `ignored`, and the count is decremented (release as above);
  - `fail` → status `failed`, and the cascade (§5.6).

**S8r retry / S8f fail.** The client decides, from the row it holds:
- final ⇔ `NonRetryableError`, or `attempts + 1 >= retry.maxAttempts`, or `retry.shouldRetry`
  returns false;
- otherwise the delay comes from the local `backoffMs` (15 §0.2: `baseDelayMs × 2^(attempt−1)`
  capped by `maxDelayMs`; `jitter: 'full' | 'equal' | 'none'`).

```sql
-- S8r
update pgprime_mq.messages set
  state = (case when $delay > 0 then 'delayed' else 'ready' end)::pgprime_mq.msg_state,
  run_at = case when $delay > 0 then now() + $delay * interval '1 ms' end,
  order_key = sign(order_key) * nextval('pgprime_mq.msg_seq'),
  attempts = attempts + 1, error = $err, stack = $stack, token = null, lease_until = null
where id = $id and token = $tok and state = 'active'
returning id
-- + [group] [global] decrements (one UPDATE per row), wake notify
```

S8f = `finish(id, 'failed', token)`. With `on_fail = 'fail'` and a parent, it is a short
transaction. It fails the child, then runs `finish(parent, 'failed', blocked)`, and so on up the tree
while each level's `on_fail` is `fail` (§5.6). It is atomic and bounded by tree depth.

As built, the lock order is message rows first, then the group row, then the queue row, in every
statement: `[deps]` comes before `[group]`, `[group]` waits for it and `[global]` waits for
`[group]` (each gated on `(select count(*) from <previous>) >= 0`). The cascade transaction first
locks the ancestor chain (nearest first), because its later statements would otherwise lock a parent
row while holding the child's group and queue rows, and deadlock with the parent's own settle on a
counted queue.

**S9 lease expiry.**
- A **gate statement of its own** (a CAS on `queues.expire_at`) lets one scanner per queue run
  every `expireScanMs`. It is separate because S9's `[global]` decrement updates the same `queues`
  row (15 §0.5 rule 6).
- Workers run it, and so does every manual `claim()` (behind the same gate, every 15 s), so a
  consumer that only claims by hand still recovers the leases of a crashed predecessor.
- An expired attempt with attempts left is re-queued in bulk (S9). The backoff is computed in SQL
  from the message's own `retry`, honouring `jitter` exactly as `backoffMs` does (D6).
- An expired **final** attempt is not finished inline. S9 returns its id, and each one goes
  through `finish(id, 'failed', expired)` with `error = 'lease-expired'`. That is the same builder,
  fragments and cascade as S8f, guarded by `state = 'active' and lease_until < now()`, so an owner
  that settled it in between wins.

```sql
-- S9g
update pgprime_mq.queues set expire_at = now()
where name = $q and expire_at <= now() - $every * interval '1 ms' returning 1
-- S9 (only when S9g returned a row)
with x as (
  select id, attempts, (retry->>'maxAttempts')::int as max_attempts from pgprime_mq.messages
  where queue = $q and state = 'active' and lease_until < now()
  for update skip locked
), up as (
  update pgprime_mq.messages m set
    attempts = m.attempts + 1, state = 'delayed',
    run_at = now() + interval '1 ms' * (case m.retry->>'jitter'
               when 'none'  then 1.0
               when 'equal' then 0.5 + random() / 2
               else random() end)
             * least((m.retry->>'maxDelayMs')::bigint, (m.retry->>'baseDelayMs')::bigint * 2 ^ m.attempts),
    order_key = sign(m.order_key) * nextval('pgprime_mq.msg_seq'),
    error = 'lease-expired', token = null, lease_until = null
  from x where m.id = x.id and x.attempts + 1 < x.max_attempts
  returning m.group_key, m.counted
)
-- + [group]: one UPDATE per group from (group_key, count(*)); [global]: one UPDATE from count(*) filter (where counted)
select (select count(*) from up) as requeued,
       (select array_agg(id) from x where attempts + 1 >= max_attempts) as exhausted   -- each → finish(id, 'failed', expired)
```

If a crash hits between S9 and an exhausted message's `finish`, that message stays `active` with
an expired lease. The next scan returns it as exhausted again, so it is finished exactly once.

**S10 retention** (inside the maintenance batch):

```sql
delete from pgprime_mq.messages where id in (
  select id from pgprime_mq.messages
  where expire_at <= now() and state in ('completed', 'failed', 'cancelled')          -- guard: only finished rows
  limit 1000 for update skip locked);
delete from pgprime_mq.messages where id in (
  select id from pgprime_mq.messages where queue = $q and state = 'completed'
  order by finished_at desc offset $keep_n limit 1000 for update skip locked);
```

**S12 defer · S13 release · S14 waitForChildren** are single token-guarded `UPDATE … RETURNING`
statements with the `[group]`/`[global]` decrements (each counter row updated once). S12 and S13 refund the claim (no attempt
counted).

S14 adds `and pending_deps > 0 and not child_failed`. On 0 rows the client re-reads the row:
- token valid and `child_failed` → `finish(id, 'failed', token)`;
- token valid and `pending_deps = 0` → `false`, and the handler carries on;
- token gone → `LeaseLostError`.

`child_failed` is on the parent's **own** row, so S14's guarded UPDATE re-reads it under the lock
(EvalPlanQual), never from another row's snapshot.

**Admin** (batched `limit $n … for update skip locked` where they touch many rows):

| API | Statement |
|---|---|
| `pause()` / `resume()` | `update queues set paused` (a committed flag every claim reads: no claim starting after `pause()` resolves takes a message) |
| `cancel(ref)` | ready/delayed/blocked → `finish(id, 'cancelled', idle)` (full fragment set: `[deps]` as a failure, `[dedup]`, `[watch]`); active → `cancel = true`, seen by the next S6; the worker aborts the signal and the handler's settle finishes it. Every move out of `active` (S8r, S12–S14) refuses a flagged row, and its owner then finishes it `cancelled` (`flagged` guard), so a short attempt that retries or defers before the next heartbeat cannot drop the cancel. When neither statement matches because the message just moved between idle and active, `cancel` tries again until it is finished or gone |
| `retry({ ids \| state, limit })` | One statement. Finished → ready, fresh `order_key`, `attempts = 0`, and **`expire_at`, `finished_at`, `result`, `error`, `cancel`, `child_failed` cleared**. A message with unresolved children (any `deps` row in `pending` or `failed`) is **refused** (`UsageError` for `ids`, skipped for `state` selections): retry its children first. A stale read can only see an unresolved dep that has since resolved, so it only ever refuses too much. A `deps` row in `failed` whose child has `on_fail = 'wait'` goes back to `pending`; the parent's count was kept, so the retried child's settle resolves it exactly once. Locks: child rows, then their `deps` rows (a settle's order) |
| `promote(ref)` | S2 without the due predicate |
| `remove(ref)` | recursive CTE over `messages_parent`; refuses `active` members; parent fragment for the root, which resolves its `deps` row as `ignored` whether `pending` or `failed` (a failed child is still counted in `pending_deps`) |
| `purge({ states, olderThanMs })` | batched deletes (+ their `until-done` dedup rows, as in `remove`) |
| `drop()` | refuses with active unless `force`; pause; closes this instance's workers and bindings of the queue (a running loop would `ready()` it back); batched delete of messages, then `groups`/`dedup`/`queues` rows |
| `get(ref)`, `list({ state, limit, after })`, `counts()` | reads; `list` is keyset-paginated on `(order_key)` / `(finished_at, id)` |
| `progress(v)` (from `ctx`) | token-guarded single-row update; also emits `[watch]` |

### 5.3 Ordering, priority, delay

`priority` is lower-first (`0` default, negatives allowed). The order is FIFO, or LIFO per message
(`lifo: true`). A promoted or retried message joins the back of its priority band, keeping its
LIFO sign. `delayMs` or `runAt` (a `Date`, compared on the DB clock).

### 5.4 The EPQ rule, worked once

Consumer B waits on the queue-row lock that consumer A holds in S4. A commits after claiming one
message. PostgreSQL re-evaluates B's `q` CTE on the **new** queue-row version, so `active` and
`rate_count` already include A's claim. A `count(*) … state = 'active'` in B would read B's
statement snapshot, taken before A committed, and over-book. The price: completions of a
globally-limited queue serialize briefly on the queue row (`[global]`), which is acceptable for a
queue that is rate-capped by definition. Unlimited queues never touch `queues` on the hot path.
The same rule makes every **counter reconcile** a lock-then-count transaction (§5.7).

### 5.5 Groups

- `send(…, { group })` sets `group_key`. Messages are FIFO within a group; groups are served
  round-robin from each worker's cursor over the skip scan (S5); manual `claim()` keeps one cursor
  per handle.
- Concurrency per group is `groups.concurrency ?? worker.group.concurrency`, and the rate per
  group is `groups.rate_* ?? worker.group.rate`. Both are counted on the locked group row (D5).
- `pauseGroup`/`resumeGroup` flip `groups.paused`; `setGroupLimits(key, { concurrency, rate })`
  overrides one group.
- Readiness is read from `messages_ready_g` itself, so there is no hint to drift. A sender inserts
  a group row only for a new group and never locks an existing one.
- Cost: one index probe per group that has ready messages, at most `$scan` per claim. Idle groups
  cost nothing, and groups that are paused or at capacity cost a probe each. Tier-2 bench: 10 000
  groups.

### 5.6 Flows

- **Dedup in flows: root only.** `dedup`/`key` are accepted on the root node and refused on inner
  nodes, leaves and `ctx.spawn`, at the type level (`ChildSendOptions` omits them) and at runtime
  (`UsageError`). A deduplicated root skips the whole flow: every child insert is conditioned on
  the root's `ins` row. The call returns `{ id: <existing root>, deduplicated: true }`; a root
  that finishes before its id is read sends the flow again, as `sendMany` does. Counts and `deps`
  therefore always match inserted rows.
- `mq.flow(node, { tx })` inserts a whole tree in **one** statement (F1). Ids come from `nextval`
  over `generate_series(1, $count)`, and parents are mapped by ordinal. Inner nodes are `blocked`
  with `pending_deps = #children`; leaves are `ready`/`delayed`. `deps` rows are inserted in the
  same statement. Nodes may target any queue.
- Dynamic children: `ctx.spawn(queue, payload, opts)` inserts a child plus its `deps` row while the
  parent is `active` (D11). Then `return ctx.waitForChildren()` (S14).
- `ctx.childResults()` reads `deps` by `parent`, keyed `'<queue>:<id>'`, with `{ status, value }`.
- A child's final failure acts by its `onFail`, inside the cascade transaction:

| `onFail` | `deps.status` | Parent effect |
|---|---|---|
| `wait` (default) | `failed` | parent stays `blocked`; visible in `childResults()` |
| `fail` | `failed` | `update messages set child_failed = true where id = $parent returning state` (as built in the child's own statement, and whatever the parent's state: a parent that was `ready` or `delayed` would otherwise block forever on its next S14). This locks the parent, child → parent order. If it returns `blocked`, then in the same transaction `finish(parent, 'failed', blocked)` runs (`error = 'child <queue>:<id> failed'`, full fragment set), and the parent's own `onFail` applies one level up. Otherwise the parent's next S14 sees the flag on its own locked row and fails itself |
| `ignore` | `ignored` | `pending_deps − 1`; released if it reaches 0 |

### 5.7 Consumer loop and maintenance

- **Claim**: `free = concurrency − running`, capped by `localRate`. A claimed message starts
  immediately; nothing is prefetched beyond free slots, because the lease runs from the claim.
- **Idle**: the loop waits on events' `waker()` (wake NOTIFY | `'gap'` → immediate | `pollMs`,
  default 5 000), the S2 timer (a duration from `db_now`), or `limited_until`, whichever comes first.
- **Settle**: a resolved handler → S7. A returned sentinel (`ctx.defer`, `ctx.rateLimit`,
  `ctx.waitForChildren`) → S12/S13/S14. A throw → S8r/S8f. A guarded write returning 0 rows →
  `LeaseLostError` on the worker's `error` hook, unless the message was completed in the caller's
  transaction (`ctx.complete(…, { tx })` sets a flag that makes the auto-complete a silent no-op).
- **Transactional settle.** Every tx-bound settle (`ctx.complete`, `ctx.transaction`,
  `QueueHandle.complete` and `QueueHandle.fail` with `{ tx }`) goes through one check:
  - It holds the message row, and for a grouped message its group row, until the caller commits,
    so it must be the transaction's last statement. Other settles in that group wait meanwhile;
    claims skip the row.
  - On a queue with global `concurrency` it is refused with a `UsageError`, because the `[global]`
    decrement would hold the queue row that every claim waits on.
- **Stop**: `signal` abort (or a signal already aborted at `work()`) or `await worker.close()`
  stops claiming and lets running handlers settle, with heartbeats continuing.
  `close({ graceMs })` aborts handler signals after `graceMs`; handlers that settle within it are
  released by S13, and the rest keep their lease until it expires (S9). `[Symbol.asyncDispose]` =
  `close()`.
- **Maintenance** (one consumer per queue per `maintenanceMs`, default 5 000; a CAS statement on
  `queues.maint_at` of its own), then:
  1. S10 retention.
  2. **Counter reconcile, lock-then-count** (15 §0.5 rule 3).
     - Groups: a short transaction runs
       `select … from groups where queue = $q and active > 0 … for update skip locked limit 500`.
       Its second statement (a fresh snapshot, the rows still locked) sets
       `active = count(*) filter (state = 'active')` per group.
     - The queue row: the same shape over `counted` active messages.
     - Every claim and settle that touches a counter holds that row's lock, so the count cannot
       race them.
  3. Expired dedup rows (`expire_at <= now()`), deleted under their own row lock.
  4. Flow cascade repair (pending `deps` whose child is `failed`, via `deps_pending`).

## 6. Events integration (D2)

### 6.1 Wake-ups and watching

- **Wake-ups.**
  - The wake channel is `engineChannel(schema, 'q', queue)`. S1, S2, S8r and the parent release
    `pg_notify` it. When the name is known in TS it is a bind parameter; for a parent in another
    queue it is built in SQL by events' `engineChannelSql()` fragment (`ev_` + 24 hex chars of
    `sha256(…)`, identical in both places).
  - Workers wait on `waker(db, chan, { pollMs })`, which yields `notify | gap | poll` and degrades
    to polling behind a transaction pooler. Several workers and watchers share a channel in one
    process; each gets its own `gap` (S0's ListenHub fix, 15 §0.6).
- **Watching.**
  - `handle.watch(handler)` and `handle.result(ref)` subscribe to `engineChannel(schema, 'q-watch',
    queue)`.
  - Watching needs the queue declared with `watch: true`. Every transition statement of that queue,
    in every process, then includes `[watch]`; the settling process's own watchers are irrelevant.
    The payload is `{ id, s }` (ids and state).
  - `watch()`/`result()` on an unwatched queue throw a `UsageError` naming the option.
  - `result()` subscribes **first**, then reads the row, so a fast completion cannot slip between
    the two.
  - It then re-reads the row on every `gap` **and every `pollMs`** (all pooler profiles), so a lost
    notification costs latency, never a hang.
  - `watch()` is a live, best-effort stream.
  - `result()` needs the row after completion, so `defineQueue` rejects `watch: true` together
    with `keep.completed: false` (a `ConfigError` at declaration).

### 6.2 Topic → queue bindings

```ts
mq.bind(defineSubscription(orders, 'billing', { types: ['order.paid'] }), billingQueue, {
  map?: (e: Entry<Order>) => { payload: BillingJob; key?: string; group?: string; priority?: number }
})
```

`bind` runs an events **subscription reader** whose batch handler, inside one transaction:
1. runs S1 for the batch (`sendMany`);
2. calls `ctx.commit({ tx })`.

Each entry therefore becomes **exactly one** message, which gives competing consumers, priorities,
groups (`group: e.key` for per-key FIFO) and retries for a pub/sub feed. Pub/sub itself stays in
events (15 E-D1). The payload is copied into the message, which keeps mq's retention independent
of the log's. A binding is single-reader (an events lease); throughput comes from batch size.

```ts
export type OnFail = 'wait' | 'fail' | 'ignore'
export type ChildSendOptions = Omit<SendOptions, 'tx' | 'key' | 'dedup'> & { onFail?: OnFail }
export interface FlowRoot<T = unknown> { queue: QueueDef<T>; payload: T; opts?: Omit<SendOptions, 'tx'>; children?: readonly FlowChild[] }   // dedup on the root only
export interface FlowChild<T = unknown> { queue: QueueDef<T>; payload: T; opts?: ChildSendOptions; children?: readonly FlowChild[] }
```

## 8. Failure and concurrency semantics

| Failure point | Outcome | Mechanism |
|---|---|---|
| Producer crashes before commit | no message, no NOTIFY | single statement / caller's tx |
| `IndeterminateCommitError` on send | unknown; resending with the same `key` + `dedup` is safe | dedup row |
| Consumer crashes after the claim / mid-handler | lease expires → counted attempt → backoff retry or `failed` | S9 |
| Crash after side effects, before the completion commits | **re-run** (at-least-once). With `ctx.transaction(fn)` / `ctx.complete(…, { tx })` the effects and the completion commit together | a token guard inside the caller's tx throws `LeaseLostError` and rolls back the app writes |
| `IndeterminateCommitError` on a standalone completion | re-read `state, token`: completed ⇒ done; same token and active ⇒ re-issue S7; otherwise `LeaseLostError` | |
| `IndeterminateCommitError` on a completion **inside the caller's transaction** (`ctx.transaction` / `ctx.complete({ tx })`) | re-read: completed ⇒ done (the transaction committed). Same token and active ⇒ the transaction rolled back with the app's writes, so it is **never** acknowledged alone: S8r records a failed attempt (`'indeterminate-commit'`) and the handler re-runs. Otherwise `LeaseLostError` | §7.2 |
| Lease lost while running | signal aborted; every later guarded write rejected; retried elsewhere | D6 |
| Concurrent claims | disjoint rows | `FOR UPDATE SKIP LOCKED` |
| Concurrent expiry scanners | one per interval; even ungated, the lock + `state` re-check gives one recovery | S9 gate + EPQ |
| Siblings complete together | parent released once | EPQ on the parent row |
| Crash inside the flow cascade tx | rolled back whole; S9 or the repair re-applies | §5.7 |
| Binding reader crashes mid-batch | the batch is re-read; messages and offset are in one tx, so no duplicates | §6.2 |
| Clock skew | no effect on ordering, leases or windows | D7 |
| NOTIFY lost | latency only: `gap` → immediate claim; `pollMs` caps it | `waker` |
| Pool exhausted | claims, heartbeats and settles queue in the pool; a heartbeat delayed past `leaseMs` ⇒ expiry | `heartbeatMs = leaseMs/3`; `controlDb` |
| Long caller tx holding a send | message invisible until commit; same-key dedup sends wait on it | documented |

**Guarantee:** at-least-once, and never two valid owners of a message at once. Exactly-once for
same-database effects through `ctx.transaction`.

## 9. Poolers, connections, sizing

| Concern | Direct / session pooler | PgBouncer transaction mode |
|---|---|---|
| statements, short txs, `migrate`, bindings | ✓ | ✓ (unnamed protocol, xact advisory locks) |
| wake-ups, `watch`, `result()` | ✓ (events `waker` / ListenHub) | only with pg-prime `directConnection`. Otherwise workers poll (`pollMs`) and `result()` polls the row every `pollMs` |

**Sizing.** A worker needs ≤ `concurrency` connections for simultaneous settles, + 1 claim,
+ 1 heartbeat, + whatever its handlers query. The trap is heartbeats starving behind a saturated
pool. `controlDb`, a second small `pgPrime` instance, isolates claim, heartbeat and expiry.
Recommended: `poolOptions.max ≥ min(concurrency, 10) + 2`, or `controlDb`; the M7 bench gives a
measured table.

**NOTIFY ceiling.** PostgreSQL serializes commits of notifying transactions on a global lock.
`notify: false` drops engine wake-ups; the bench measures throughput both ways (M-Q1).

- Out of scope: a dashboard, request/reply beyond `send` + `result`, time-partitioned `messages`, cross-database routing.
